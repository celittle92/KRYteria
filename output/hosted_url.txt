TWO THINGS TO EXPECT, BOTH NORMAL

1. The first request after a quiet spell takes about a minute. A free Render instance
   spins down after roughly fifteen minutes without traffic, and the first visitor wakes
   it. The health check above took 10.6 seconds on a cold start and 0.2 seconds warm.
   It is not a broken link.

2. Nothing a visitor writes survives a restart. A free instance has an ephemeral disk,
   so the SQLite file is rebuilt on every boot and redeploy. KRYTERIA_SEED_ON_BOOT makes
   that self-healing rather than fatal: the synthetic demo account is rebuilt every time,
   so the demo is always there. It is a demonstration deployment and not durable storage,
   and README.md says so rather than implying otherwise.

IF THE HOSTED LINK IS ASLEEP OR DOWN

README.md carries tested local instructions, and the app runs with no API key at all in
demo mode. The project requirements warn that a sleeping free tier is a real risk, which
is exactly why the local path is kept current rather than assumed.

The deployment redeploys automatically on every push to main (render.yaml,
autoDeployTrigger: commit). A deploy therefore resets the database — avoid pushing while
somebody is mid-session on the hosted app.
