Every person, entry, observation and assessment is invented. Nothing describes a real
person. The analysis in the proof-point entries is genuine agent output from a live run
(58 model calls, $0.0431), frozen into data/characters/*.json so the hosted app shows
real output without spending credits on every restart.

TWO THINGS TO EXPECT, BOTH NORMAL

1. The first request after a quiet spell takes about a minute. A free Render instance
   spins down after roughly fifteen minutes without traffic, and the first visitor wakes
   it. Measured: 10.6 seconds on a cold start, 0.2 seconds warm. It is not a broken link.

2. Nothing a visitor writes survives a restart. A free instance has an ephemeral disk,
   so the database is rebuilt on every boot and redeploy. KRYTERIA_SEED_ON_BOOT makes
   that self-healing rather than fatal: the nine characters are rebuilt every time. It
   is a demonstration deployment, not durable storage, and README.md says so.

IF THE HOSTED LINK IS ASLEEP OR DOWN

README.md carries tested local instructions, and the app runs with no API key at all in
demo mode. The project requirements warn that a sleeping free tier is a real risk, which
is why the local path is kept current rather than assumed.

The deployment redeploys on every push to main (render.yaml, autoDeployTrigger: commit).
A deploy resets the database, so avoid pushing while somebody is mid-session.
